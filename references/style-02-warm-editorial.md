# Style 02：暖色编辑插画 · 类比动画（warm-editorial）

- 状态：✅ 用户认可。2026-11-03，《Super-agent》科普视频第二版，用户原话：“这次是可以的”；随后要求把做法沉淀成 skill
- 制作者：Claude Code（云端会话）
- 路线：**程序化插画动画**（HTML/SVG 插画 + CSS 动画 + Playwright 逐帧确定性渲染）。**不用 AI 视频生成**，所以每一帧都可控、可复现、改字即可重渲
- 引擎：[`engines/style-02-warm-editorial/`](../engines/style-02-warm-editorial/)（直接复制就能用，带一键 `build.sh`）
- 代表作：`demo/style-02-super-agent-preview.mp4`（540×960 压缩预览版；原片 1080×1920、30fps、4:52、-16.3 LUFS）、`demo/style-02-super-agent-cover.png`、`demo/style-02-frames.jpg`
- 视觉灵感：Anthropic 的审美（暖纸色、陶土橙、衬线标题、线描插画）。**只借鉴审美，画面里不出现对方的 logo、字标和名字**
- 适用题材：技术架构、AI 产品机制、方法论；概念多、需要多个生活类比逐个讲清楚的题材。没有 AI 视频生成能力的环境也能做
- 不适用：需要电影感运镜和真实场景的题材；60 秒以内的强情绪短片（这类优先用 Style 01）

## 与主流程的关系（2026-11-03 用户裁定后）

Style 02 遵守主流程的全部通用规定和质量红线。下面是本风格的**专属特点**（主流程允许各风格自定）：

| 项目 | 主流程 | Style 02 的做法 |
|---|---|---|
| 红线 1：禁止程序化框图当主体 | 通用 | 主体是**有角色、有道具的插画场景**（餐厅、门铃、办公桌、洗衣机、泳池），不是方框和连线。第一版深色卡片 PPT 就是因为违反这条被否决的 |
| 红线 2：概念被具象地演出来 | 手法由风格定 | **每个机制一个生活类比**（餐厅 / 门铃 / 办公桌 / 洗衣机 / 救生员），类比后面紧跟术语；开场和结尾用“你盯着 AI → AI 替你盯着”收束 |
| 红线 3：讲到哪演到哪 | 通用 | 用 `A(第几句, 动画, 延迟)` 把画面变化精确绑定到每句旁白 |
| 红线 4：同一角色贯穿 | 通用 | 全片统一一种小人（圆头 + 圆角身体）；陶土色 = AI 或主角，天蓝色 = 你 |
| 红线 5：画面一直在动 | 通用 | 舞台全程缓慢推镜，背景圆斑漂移，每屏至少一个循环动画；场景切换带淡入淡出和上移 |
| 红线 6：钩子在前 | 通用 | 开场用“AI 越能干，你怎么越忙？”加一个硬数字 |
| 画幅 | 竖屏 9:16 | 1080×1920 |
| 时长 | 随选题 | 一个场景约 20–30 秒；示例 11 个场景 4:52。想短一点就取 ★ 场景（见类比手册） |
| 署名 | 「白羊武士」 | 每帧页脚自动显示「白羊武士 · 资料来源：…」（`META.author` 默认就是白羊武士）；封面页脚也带署名 |
| 结尾 | 不做“关注我”尾钩 | 最后一个场景是总结金句 + 互动提问（评论区 / 收藏 / 关注），属于正片内容，不是独立的尾钩段 |
| 封面 | 版式由风格定 | 浅色纸感版式：衬线大字 3 行 + 副标题 + 4 个类比标签 + 主角小人 + 署名 |
| 字幕 | 烧录、≤3 行 | 米白卡片 + 黑描边 + 硬投影，46px |
| 配音 / 响度 | 按段 TTS | edge-tts `zh-CN-YunxiNeural +12%`，逐句生成；整体约 -16 LUFS，人声说话时音乐自动压低约 15dB |

> 仓库里的 demo（`demo/style-02-*`）是在“署名必须为白羊武士”这条规定之前做的，成片页脚还没有署名；封面已补上。新片用当前引擎做，会自动带上署名。

## 制作流程（Style 02）

1. **吃透素材**：同主流程第 1 步。X 长文的全文可以从公开 embed 接口拿（`api.fxtwitter.com/<user>/status/<id>` 的 `tweet.article.content.blocks`）。需要登录的站点（比如小红书）不要绕过反爬，请用户提供素材。
2. **写类比脚本**：每个机制配一个能画出来的生活类比，类比后面紧跟术语；每句 18–40 字；原文的限定语（“初步实验”“架构思路”“非正式产品”）必须保留。结构和类比库见下文。
3. **写分镜** `scenes.js`：每个场景 = `lines`（旁白）+ `html()`（插画和动画绑定）。
4. **预览**：`STEP=preview bash build.sh` 会在每句旁白结尾截一张图。把预览图拼成联系表，逐张看：有没有重叠、字幕是否超 3 行、元素有没有按时出现和退场。
5. **全量渲染 + 合成**：`bash build.sh`（按 CPU 核数并行，约 8,800 帧，4 核约 15 分钟，放后台跑），会合成人声、配乐、转场音效并出封面。
6. **交付验收**：ffprobe 看分辨率和时长；整体响度约 -16 LUFS；每 30 秒抽一帧；封面回读检查；文案。没有完整看过、听过的部分要如实告诉用户。

### 字体

- 标题、大数字、印章：**Noto Serif SC 900**（`@fontsource/noto-serif-sc`）
- 正文、字幕、标签：**Noto Sans SC 400/700/900**（`@fontsource/noto-sans-sc`）
- 两个包都从 npm 安装，用本地 `file://` 引用。CJK 字体按 unicode-range 分片，渲染前必须 `document.fonts.load(…, 实际文本)`，`render.js` 已经处理。

### 插画语法

- **描边**：所有形状 4–5px `--ink` 描边，圆角 12–28，线端 `round`。
- **卡片**：ivory 底，4px ink 描边，圆角 28，**8px 8px 0 硬投影**（不用模糊阴影），这是本风格的标志。
- **人物** `person(x,y,scale,color)`：圆头（ivory）+ 圆角矩形身体（角色色）+ 两点眼 + 弧线微笑。全片统一这一种小人；陶土色固定给 AI 或主角，sky 色给“你”。
- **窗口** `win(x,y,w,h,color,label)`：圆角窗，标题栏上色，里面放占位文本条。
- **道具**：用最简单的几何形拼：房子 = 三角形 + 矩形，云 = 几段弧，数据库 = 椭圆柱，档案柜 = 矩形 + 抽屉，电梯用 🛗。emoji 只作为点缀图标，不当主体插画。
- **文字层级**：`.k`（衬线 46px）是卡片标题，`.d`（30px slate 色）是说明，`.analogy`（药丸形）写“≈ 类比词”。

节奏规则：
- 每句旁白开始后 0.1–0.4s 出现第一个变化；同一句里多个元素按 0.2–0.5s 错开出场。
- 演示“过程”的场景（比如 bug → 复现 → 修复 → 确认），按步骤间隔 0.55s 依次出现，并用箭头描线连起来。
- 一个场景内部如果要讲两个类比，用 `data-out` 把第一组清场，再上第二组，不要堆在一起。

### 转场

- 每个场景前 0.45s 舞台淡入，同时上移 40px；最后 0.4s 淡出，同时上移 30px。舞台全程以 0.12%/秒的速度缓慢放大，制造推镜感。
- 标题随场景淡出。字幕每次换句时，0.2s 内从 35% 透明度淡入，同时上移 10px。
- 音效：场景切换点前 0.35s 放一声 0.7s 的粉噪“呼”（带通 900Hz，正弦淡入淡出），音量 35%。

### 封面（3:4，1080×1440，`engines/style-02-warm-editorial/cover.html`）

- 同一套色板；左上是陶土橙圆点 + `系列 · N 分钟看懂`。
- 3 行衬线 122px 大标题，最后一行放 `<em>` 强调词（clayd 色 + 下划条）。
- 一行副标题（46px slate 色）：写清“谁的什么设计”。
- 4 个硬投影药丸标签，每个是“emoji + 类比名”（例：🍽️ 餐厅两层架构）。
- 右下角放主角小人；两团角落圆斑。

### 配乐

- `music.py`：84 BPM，Am7–Fmaj7–Cmaj7–G6；三角波 + 正弦的铺底和弦、拨弦琶音（带回声）、正弦贝斯、轻柔的 kick/snap/hat；整体做 6.5kHz 低通，听感偏暖。
- 混音：人声 -16 LUFS；音乐先归一到 -24 LUFS，再按人声做 sidechain 压低（threshold .03、ratio 6、attack 40ms、release 600ms），最后过 -1dBFS 限幅。

### 禁忌（用户否决过 / 踩过的坑）

- ❌ 静态卡片截图 + 配音（第一版深色 PPT 风被否决：“就是纯 PPT 幻灯片”）。
- ❌ 一屏堆满字。字都放进字幕，舞台上只放图形和 ≤ 12 字的标签。
- ❌ 用模糊阴影、渐变霓虹、深色底。这些会破坏纸感。
- ❌ 字幕超过 3 行。超了就拆句，或者缩短旁白。
- ❌ 在画面里放 Anthropic 或任何第三方的 logo、字标。

## 类比脚本手册

用户对第一版的反馈是“要多一些类比、比喻、参考，要生动”。第二版按下面的方法重写后，用户确认通过。

### 原则

1. **一个概念对应一个日常场景**，而且这个场景要能画出来。先问自己：这个概念在餐厅、办公室、家里、交通、医院、快递里，对应的是什么？画不出来的类比，就换一个。
2. **类比要和机制同构**，不能只是表面像。“Router 不下厨”对应原文“Router 层不执行任务”；“电梯一次载多人”对应“批处理摊薄每次决策的耗时”。讲完类比，紧接着一句点名术语（“这叫 Inline”），让观众把类比和概念连起来。
3. **先讲痛感，再讲解法**。开场用观众自己的处境（“开五个窗口像带五个实习生”），而不是先讲定义。
4. **用数字收口**。每个场景最多一个硬数字，数字要能对应原文。
5. **原文的限定语必须保留**：“初步实验”“架构思路”“非正式产品”等，放进倒数第二个场景，不要删。
6. **句子要能做字幕**：每句 18–40 字，一句只讲一件事；英文术语前后加空格；尽量少用括号。

### 11 场景结构（约 4–5 分钟；短版按 ★ 取 6–7 个场景）

| # | 场景 | 作用 | 示例写法 |
|---|---|---|---|
| ★1 | 开场钩子 | 观众的处境 + 一个硬数字 + 引出主角 | “开五个对话窗口，就像同时带五个实习生……最多盯住三到五个” |
| ★2 | 问题 | 现状的 3 个痛点，每个痛点配一个画面 | 一次只接一个电话的客服 / 隔离的小房间 / 电脑合盖它也下班 |
| 3 | 概念 | 一句话定义 + 3–4 个特征 + 拟人化的总结 | “靠谱的老同事：记得事、干得快、有眼力见、不掉线” |
| ★4–8 | 第 N 招 | 每招一个主类比场景，“第一招……想象一家餐厅” | 见下方类比库 |
| ★9 | 数据 | 对比柱 + 滚动数字 + 一个类比解释数据 | 15.7 vs 29.5 分钟；6.4→1.6 秒“像电梯” |
| 10 | 局限 + 免责 | 3–4 个开放问题 + 原文限定语 | “提醒一下：原文讨论的是架构思路……” |
| ★11 | 总结 + 互动 | 角色反转的一句话 + 提问 | “以前是你盯着 AI，以后是 AI 替你盯着”“评论区聊聊” |

| 半双工 vs 全双工 | 打电话插不上嘴 vs 开洗衣机：按下启动就走人，好了叫你 | 说个不停的气泡 vs 转动的滚筒 + “叮” |
| 多渠道措辞 | 群里像同事一样简短 vs 邮件写正式报告 | 手机群聊（≤100 字章）vs PR 文档（结构完整章） |
| 计算与环境分离 | 大脑上云，双手留在你的电脑上，只装一个小遥控器 | 云里的 🧠 + 数据库 + 笔记本 + 遥控器信号波 |
| 进度监控 Watchdog | 泳池救生员：不只看人在不在水里，还看是不是在原地扑腾 | 瞭望塔 + 来回扫的探照灯 + 扑腾的泳者 |
| 人机角色转变 | 从操作工变成签字的人 | “批准 ✓”印章 |

## 分镜写法（scenes.js）

`scenes.js` 同时在浏览器（`stage.html` 用 `<script>` 加载）和 Node（`build.sh` 用它导出 `script.json`）里运行，所以只能用纯 JS，不要用 import 或 require。

### 骨架

```js
const A = (at, a = 'fu', d = 0, x = '') => ` data-at="${at}" data-a="${a}" data-d="${d}" ${x}`;
const C = { ink:'#141413', clay:'#D97757', clayd:'#C6613F', sage:'#788C5D', sky:'#6A9BCC', kraft:'#D4A27F', oat:'#E3DACC', paper:'#F0EEE6', ivory:'#FAF9F5', fig:'#C46686', heather:'#CBCADB', mute:'#87867F' };
// helper：person(x,y,s,col)、win(x,y,w,h,col,label)、svg(inner)、card(x,y,w,inner,at,anim,d,bg)
// 直接从 engines/style-02-warm-editorial/example/scenes.js 复制

const SCENES = [
  { id: 'hook',                 // 英文 id
    chap: '开场',                // 页眉章节名
    title: 'AI 越能干，<br>你怎么<em>越忙</em>？',   // 2 行，一个 <em>
    lines: ['第 0 句旁白', '第 1 句', '第 2 句', '第 3 句'],   // 3–5 句
    html: () => `...舞台内容（936×880 坐标系）...`,
    dims: [[2, '.ill']],        // 可选：第 2 句开始时，把 .ill 降到 10% 透明度
  },
];
const META = { series: 'AI 架构科普', source: '作者《原文标题》' };
if (typeof module !== 'undefined') module.exports = { SCENES, META };
```

### 动画绑定：`A(lineIndex, anim, delay)`

- `data-at`：第几句（从 0 开始）。这个元素在那句旁白开始的时刻 + `delay` 秒入场。
- `data-a`：入场动画名，可选：`fu fi pop sl sr drop stamp flip merge grow growx drawa`。
- `data-out="k"`：第 k 句开始时淡出（写在同一个元素上，和 `A()` 一起用）。
- 同一元素的子元素里，带 `class="draw"` 并设了 `pathLength="1"` 的路径，会在父元素入场后 0.2s 自动描线。
- 没写 `A()` 的元素从场景一开始就可见（会跟着舞台淡入）。

```html
<g${A(1, 'pop', .3)}> … </g>                         <!-- 第 1 句开始 0.3s 后弹出 -->
<div class="card"${A(2, 'fu', 0)} data-out="3">…</div> <!-- 第 2 句上浮，第 3 句淡出 -->
<path class="draw-slow" pathLength="1"${A(3,'drawa',.6)} …/>   <!-- 直接描线 -->
```

### 循环动画（让画面一直在动）

加 class 就行：`loop-bob loop-shake loop-ring bell flame spin orbit wave wavex scan splash zzz lid flow loop-eye loop-sand`。

- 想错开相位：`style="animation-delay:-0.37s"`（负数延迟）。
- 沿路径移动：`class="mover|mover-slow|dot|drop|pass"` + `style="offset-path:path('M… C…');offset-rotate:0deg"`。SVG 元素也能用 `offset-path`（Chromium 已验证）。
- 绕圈：`<g class="orbit" style="transform-origin:cx cy"><g class="cr">${person(...)}</g></g>`。`cr` 负责反向转，让人物保持直立。

### 数字滚动

```html
<span class="cnt" data-count="15.7" data-at="1" data-d=".3" data-dur="1.6">0</span>
<span class="cnt" data-count="1.6" data-from="6.4" data-at="3" data-d=".8" data-dur="2.4">6.4</span>
```

### 柱状图

```html
<div class="hbar" style="--w:53%;background:#788C5D"${A(1,'growx',.3)}>…</div>
```

### 布局约定

- 舞台是 936×880，**用绝对定位**：HTML 元素用 `.abs` / `.card` + `left/top`，SVG 用 `viewBox="0 0 936 880"`。
- 卡片宽度常用两栏：`452 + 32 间距 + 452`。
- 舞台上的文字 ≤ 12 字，长内容放旁白里。
- 一个场景讲两个类比时，第一组元素加 `data-out`，第二组在同一句开始入场。

### 常见坑（已经在引擎里处理，或必须遵守）

1. **SVG 元素自带 `transform` 属性时，CSS 动画会覆盖它**，元素会跳回原点。引擎会自动把这类元素包进一个 `<g>`，由外层承担动画。但**循环 class 不能直接加在带 transform 属性的元素上**，要外面再套一层 `<g class="loop-xxx">`（`person()` 返回的 `<g>` 自带 transform，所以要包一层）。
2. 一个元素上不要同时放“入场动画”和“循环动画”：两者都写 transform，后者会覆盖前者。入场写在外层，循环写在内层。
3. `.card` 是 `position:absolute`。要放进流式布局时，加 `style="position:relative"`。
4. 字幕超过 3 行就会压到页脚。预览时专门检查最长的句子。
5. 一个 HTML 元素只能有一个 `class` 属性，重复写的话后面那个会被忽略。


## 技术流水线与踩坑

### 依赖

| 依赖 | 用途 | 安装 |
|---|---|---|
| Node + `playwright`（自带 Chromium） | 逐帧渲染、封面 | 云端容器已预装：直接 `require('playwright')`，不要再跑 `playwright install` |
| ffmpeg / ffprobe ≥ 6 | 编码、混音、响度测量 | 系统包 |
| Python venv：`edge-tts`、`numpy` | 配音、配乐合成 | `python3 -m venv venv && venv/bin/pip install edge-tts numpy` |
| `@fontsource/noto-serif-sc`、`@fontsource/noto-sans-sc` | 中文衬线体和黑体 | `build.sh` 会自动 `npm i` |

### 时间模型（`timing.py`）

```
场景时长 = LEAD 0.7s + Σ(每句配音时长 + GAP 0.3s) − GAP + TAIL 0.6s
starts[i] = 第 i 句在本场景内开始的秒数
```

- 动画、字幕、计数器全部从 `starts` 推出来，所以改了旁白文字，重跑一遍就自动对齐。
- `build_audio.py` 用同一份 `timing.json`，把每句配音用 `adelay` 放到全片的绝对时间点上；场景切换点前 0.35s 放转场音效。

### 逐帧渲染（`render.js` + `stage.html`）

- `setup(sceneIndex, starts, dur, total)`：插入场景 HTML；把 `data-at/data-a/data-d/data-out` 转成带延迟的 CSS `animation`；把带 transform 属性的 SVG 元素包进 `<g>`；重置字幕缓存（这个 bug 修过：同一个页面连续渲染多个场景时，字幕会停在上一场景的句子上）。
- `seek(t)`：`document.getAnimations().forEach(a => { a.pause(); a.currentTime = t*1000 })`，再用 JS 算字幕、计数器、进度条、舞台推镜和淡入淡出、背景圆斑漂移。
- 每帧截一张 JPEG（quality 92），通过 `image2pipe` 喂给 ffmpeg（libx264 crf18、yuv420p、30fps），每个场景出一个 mp4，最后 concat。
- `node render.js all` 按场景时长贪心分组，并行数等于 CPU 核数。**示例数据：约 8,800 帧，4 核约 15 分钟，记得放后台跑**。
- `node render.js preview`：每句结束前 0.5s 截一张静帧，这是最便宜的检查手段。

### 混音参数（`build.sh`）

```
voice  → loudnorm I=-16 TP=-1.5 LRA=11
music  → loudnorm I=-24 TP=-3 → sidechaincompress(由 voice 触发) threshold .03 ratio 6 attack 40 release 600
sfx    → volume .35
amix normalize=0 → alimiter limit .89 → AAC 192k
```

成品实测整体响度约 -16.3 LUFS。说话时音乐比人声低约 15dB，句子间隙里会回升。

### 画幅

当前 `stage.html` 只针对 1080×1920 排版（主流程规定竖屏 9:16）。以后如果要做横版（4:3 或 16:9）：
1. 设置环境变量 `VW/VH` 让 `render.js` 用新的视口；
2. 重写 `stage.html` 的版面：标题区放左栏、舞台放右栏、字幕放底部一条，每个场景的舞台坐标都要重新检查；
3. 建议做成 `engines/<engine-id>/` 下的一个新引擎，登记为新风格或新变体，不要直接改 `engines/style-02-warm-editorial/`。


### 取原文

- X/Twitter：`https://cdn.syndication.twimg.com/tweet-result?id=<id>&token=a` 返回推文元数据；长文（`x.com/i/article/…`）的全文用 `https://api.fxtwitter.com/<user>/status/<id>`，在 `tweet.article.content.blocks[]` 里（`type` + `text`）。`x.com` 页面本身要登录。
- 小红书：分享短链能解析出笔记 ID，但正文和视频要登录才能看。**被拦了就停**，请用户提供截图、文字或视频文件，不要换 UA 冒充爬虫或手机去绕。

### 踩过的坑

| 现象 | 原因 | 解决 |
|---|---|---|
| edge-tts 报 DNS 错误 `speech.platform.bing.com` | aiohttp 不读 `HTTPS_PROXY` 环境变量 | 显式传 `proxy=os.environ['HTTPS_PROXY']`（`tts.py` 已处理） |
| SVG 元素动画后跳到 (0,0) | CSS transform 覆盖了 `transform` 属性 | 外面包一层 `<g>`（`setup()` 已自动处理） |
| 绕圈的小人消失了 | 反向旋转的 class 直接加在带 transform 的 person `<g>` 上 | 用 `.orbit>.cr` 包装层 |
| 新场景的字幕显示的是上一场景的句子 | 字幕按句号缓存，跨场景没有重置 | `setup()` 里清掉 `sub.dataset.li` |
| 字幕压到页脚 | 3 行字幕 + 48px 字号太高 | 字号 46px，页脚移到 top 1650；旁白每句 ≤ 40 字 |
| 两个大元素叠在一起（比如大数字被印章盖住） | 上一句的元素没退场 | 给旧元素加 `data-out` |
| 偶尔出现豆腐块缺字 | CJK 字体分片没加载 | 渲染前按实际文本 `document.fonts.load` |
| 第一版被说“像 PPT” | 静态截图 + 拼接，没有任何运动 | 每句旁白都要触发画面变化，每屏至少一个循环动画 |

### 示例的数据规模（参考）

46 句旁白，配音约 4 分 40 秒；11 个场景、8,773 帧；成片 34MB；全流程（含预览迭代）约 1 小时，其中全量渲染约 15 分钟。


## 脚本全文（《Super-agent》，11 场景，46 句）

**01 开场｜AI 越能干，你怎么越忙？**

0. 你有没有这种感觉：AI 越来越能干，你却越来越忙？
1. 开五个对话窗口，就像同时带五个实习生，每个都得你盯着。
2. DeepSeek Harness 团队发现，一个人最多只能盯住三到五个会话。
3. 瓶颈不在 AI，而在你的注意力。他们的解法，叫 Super-agent。

**02 问题｜今天的 AI，像一次只接一个电话的客服**

0. 今天的 AI 助手，像一个一次只能接一个电话的客服。
1. 每个会话都是一间隔离的小房间，房间之间不通气，你得自己跑来跑去传话。
2. 它干长活的时候，你说什么它都听不见；你的电脑一合盖，它也跟着下班。
3. 所以单个任务看模型能力，多任务，全看你一个人的脑子够不够用。

**03 概念｜从“一次性对话”到全职助理**

0. Super-agent 想做的，是把 AI 从“一次性的对话”，变成一个“全职助理”。
1. 它一直是同一个它：不管你在群聊、GitHub 还是邮件里找它，它都记得前因后果。
2. 它有四个特点：持续、高效、主动、常驻。
3. 就像一个靠谱的老同事：记得事、干得快、有眼力见、不掉线。

**04 第一招｜两层架构：一家餐厅**

0. 第一招，两层架构。想象一家餐厅。
1. Router 是前厅经理：招呼客人、记下需求、把单子派给后厨，自己从不下厨。
2. Worker 是后厨的厨师：每人一个灶台，专心做一道菜，互不干扰。
3. 厨师不直接跟客人说话，菜好了交给经理端出去，所以你始终只面对一个人。
4. 高峰期经理还会把排队的单子一次性合并处理，就像电梯一次载多人，越忙越划算。

**05 第二招｜事件驱动：听见门铃就开门**

0. 第二招，事件驱动。它不等你开口，而是自己留意周围发生的事。
1. 群消息、邮件、日历提醒、代码评审、CI 结果，都是触发它的“门铃”，叫 Trigger。
2. 但门铃太多了。先让“门禁”用代码规则刷掉大部分噪音，拿不准的再请“前台”大模型来判断。
3. 已经有人负责的事，比如同一个 PR 的后续消息，就像快递直接送到收件人工位，不用再过前台。

**06 上下文｜上下文窗口是一张办公桌**

0. 怎么喂给 AI 信息？他们把上下文窗口当成一张办公桌。
1. 马上要用的文件，直接摊在桌面上，这叫 Inline；
2. 太厚的资料，放进档案柜，桌上只留一张写着编号的便签，这叫 Spill。
3. 每样东西都有编号，AI 可以像侦探一样顺着线索墙一路往回查，这叫 Chain of Recall。
4. 它还会先斩后奏：有人报 bug，它先在后台悄悄复现、修好，确认了才开口。

**07 第三招｜全双工：从打电话到洗衣机**

0. 第三招，全双工。传统 AI 像打电话：它说话的时候，你插不上嘴。
1. 新的做法像开洗衣机：按下启动立刻走人，洗好了它会叫你，中间你随时可以吩咐别的事。
2. 它还懂得看场合说话：在群里像同事一样简短，一条不超过一百字；
3. 到了 GitHub 和邮件里，就写背景、改动、验证结构完整的正式报告。

**08 第四、五招｜大脑上云，双手留在原地**

0. 第四招，把大脑和双手分开。
1. 大脑，也就是 AI 的主循环，搬到云端常驻，记忆存进数据库，你关电脑它也不下线。
2. 双手留在你的电脑上：代码、环境、密钥都不用搬，只装一个小小的遥控器，按需远程干活。
3. 第五招，看门狗。就像泳池救生员，不只看人还在不在水里，还要看他是不是在原地扑腾。

**09 实验｜效果怎么样？数据说话**

0. 效果如何？团队用约三百条模拟消息，做了对比实验。
1. Super-agent 的 95 分位完成时间是 15.7 分钟；
2. 单会话方案最慢拖到 29.5 分钟，差不多是两倍。
3. 消息越密集，Router 每次决策反而越快，从 6.4 秒降到了 1.6 秒。

**10 难题｜还没解决的四个问号**

0. 当然，还有不少难题没解决。
1. 跑上几个月，长期记忆怎么办？没有会话窗口，人又该怎么和它协作？
2. 不同团队的 AI 之间怎么安全对话？钥匙怎样做到能用、但 AI 看不见？
3. 提醒一下：原文讨论的是架构思路，原型也不是 DeepSeek 的正式产品。

**11 总结｜从盯着 AI到AI 替你盯着**

0. 一句话总结：以前是你盯着 AI 干活，
1. 以后是 AI 替你盯着这些事，只在需要你拍板的时候来找你。
2. 你从操作工，变成了签字的那个人。
3. 你想要这样一个 AI 同事吗？评论区聊聊。
